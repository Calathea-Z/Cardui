# Reconnect

Date: October 7, 2026
Status: Approved 2026-10-07
PR:

## Increment

A bank connection that still exists can be repaired in Plaid Link. Connections shows Reconnect when the latest sync failed. A followed debt whose sync is failing opens the same repair. After the person finishes, that institution is synced. The stored access token does not change, and it is not returned.

A removed bank link has no item to repair. Reconnect on that debt still opens Connections.

The approved `Domain/<feature>` wording is now in the type-file and domain rules.

## Decision

Repair uses Plaid update mode. `POST /api/plaid/{id}/link-token` builds a link token for that household item. The request sends the stored access token and does not ask for products. A new connection still uses `POST /api/plaid/link-token` and still asks for Transactions only.

Finishing a repair does not exchange the public token. Plaid keeps the same access token. Cardui then runs the existing sync for that institution, which refreshes accounts and can clear the failure.

Reconnect is offered when the latest sync failed after the last success, or failed with no success. That is the same rule a followed debt already uses for "Sync failing". A later success does not offer Reconnect. A stale debt still offers Refresh, not Reconnect.

On a debt, Reconnect opens Link only when the sync is failing and the account still has a bank item. "Bank link removed" still goes to Connections, because the item and its access token are gone. Update balance stays beside Reconnect on a failing sync.

A failing sync and a removed bank link use the error alert: the icon, the sentence, and the light red wash. Reconnect is the tinted error button, on the debt and on Connections. An old balance uses a notice with a light wash, and Refresh is the filled button. Update balance stays outline. The amount still says Synced with its date, because that is the last balance the bank sent.

The folder rule Zach approved is: a Domain type goes in `Domain/<feature>` for the feature that owns it, and a rule that several features read stays at the `Domain` root. `PlaidItemSync.LastAttemptFailed` is that repair rule, in `Domain/Plaid`. The debt freshness rule calls it.

## Changes

- Update-mode link token for one household item. The response is only the link token.
- Connections shows Reconnect on a connection that needs repair, then syncs it.
- A failing followed debt opens that repair. A removed link still opens Connections.
- `NeedsRepair` on the institution list. No new column.
- The `Domain/<feature>` sentence is in `.cursor/rules/backend-type-files.mdc`, `backend-domain-rules.mdc`, and `AGENTS.md`.

## Data changes

No migration. The model matches `20261007193207_AddAccountCreditLimit`. Restart the API so the new route and `needsRepair` are available.

Creating a link token does not write a row. Finishing a repair syncs that institution, so it can change account balances, today's snapshot, and the sync timestamps. The stored access token is not replaced. A removed bank link is not restored.
