# Narrow tools

## Increment

Phase 4 item 3. The assistant gets a closed set of tools. A tool can read
one household summary, propose a fact, request a calculation, compare a
supported scenario, or draft a plan change. The tools call the services
direct editing uses. A proposal or a draft is returned and not saved. No
model or price is chosen. There is no chat screen and no live OpenAI call.
Items 4–9 have not started.

## Decision

- The tools are methods on `IPlanningTools`. There is no route and no
  screen. `IPlanningModel` still sends no tools. A later item can call these
  methods. This one does not.
- A summary is cash, the debt summary, income, saved bills, savings, living,
  allocation, or the saved plan versions. The read stays in the signed-in
  household. Saved bills are the bill list. A suggestion is left out.
- A proposed fact uses the same field rules as saving that fact, and the
  same household checks for a person or an account. Income, a bill, a debt,
  a savings row, a monthly contribution, and an allocation can be proposed.
  Nothing is inserted or updated, and no money is moved. A duplicate name is
  not rejected here, because the proposal does not say whether it is a new
  row or a change to one that already exists. The save path still rejects a
  duplicate when a later item applies it.
- A suggestion key on a proposed bill is rejected. Noticing a repeated
  payment does not make it a bill.
- A savings account has to be cash in this household. An account another
  goal already follows is rejected. This proposal does not name an existing
  goal, so it cannot keep that goal's account.
- A calculation and a scenario comparison call `IPlanService`. The supported
  amounts are extra each month, income loss, a windfall, flexible spending,
  cash to keep, payoff priority, and how much freed cash to keep. A
  restructuring comparison calls `IRestructuringService` for one
  consolidation loan, balance transfer, or replacement loan. The offer is
  not saved and is not treated as approved.
- A plan draft calls `ISavedPlanService.GetPreviewAsync`. It does not call
  `SaveDraftAsync` or `AcceptAsync`.
- The tools do not write a conversation. Living and savings summaries are
  the pages those screens already return, so a savings row can include an
  account mask. No tool returns a bank access token, a transaction, or a
  transaction description. What may be sent to the model stays in item 8.

## Changes

- `IPlanningTools` reads a summary, proposes a fact, calculates, compares,
  and drafts a plan change.
- `PlanningToolRules` checks the summary and rejects a suggestion key on a
  proposed bill.
- The field checks call the same domain rules the save methods call. The
  household checks call the read methods on the accounts, profile, and
  savings services.

## Data changes
